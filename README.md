# Сололевелинг

RPG-трекер саморазвития: ветки навыков, XP, ранги E–S, серия дней, тренировки, ГТО.
Работает в браузере и на телефоне (можно добавить на главный экран). Данные хранятся на устройстве и, после входа, синхронизируются через Supabase.

## Что в папке

| Файл | Зачем |
|---|---|
| `index.html` | всё приложение |
| `vendor/supabase.js` | клиент Supabase 2.119.2 (лежит в репозитории, без внешнего CDN) |
| `supabase/schema.sql` | таблица и правила доступа (RLS) |
| `manifest.webmanifest`, `icon*.png`, `icon.svg` | иконка и установка на телефон |
| `.nojekyll` | чтобы GitHub Pages отдавал файлы как есть |

## 1. Настроить Supabase (один раз)

1. **SQL Editor → New query** → вставить `supabase/schema.sql` → **Run**.
2. **Authentication → URL Configuration**:
   - **Site URL**: `https://<логин>.github.io/<репозиторий>/`
   - **Redirect URLs**: добавить тот же адрес.
   Без этого ссылки из писем (подтверждение почты, сброс пароля) поведут не туда.
3. **Authentication → Sign In / Providers → Email**: включено. Подтверждение почты лучше оставить включённым.
4. Зарегистрироваться в приложении (вкладка «Данные» → «Облако»), подтвердить почту.
5. **Важно:** после того как нужные аккаунты созданы, выключить **Allow new users to sign up** (Authentication → Sign In / Providers). Чужие данные посторонние и так не увидят, но так никто не сможет заводить аккаунты и забивать базу.

## 2. Опубликовать на GitHub Pages

1. Создать репозиторий (можно приватный, если план GitHub позволяет Pages для приватных; сама страница всё равно будет открыта по ссылке).
2. Загрузить содержимое этой папки в корень репозитория.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → Save.
4. Через минуту сайт будет на `https://<логин>.github.io/<репозиторий>/`.

## Про ключи

- В `index.html` лежит **publishable**-ключ (`sb_publishable_…`). Он и задуман публичным: защищают данные правила RLS из `schema.sql`.
- **Secret / service_role ключ никогда не класть в код и в репозиторий.** Он обходит все правила доступа.

## Как работает синхронизация

- Каждая запись сразу сохраняется на устройстве, через 1,5 секунды уходит в облако.
- При входе, открытии и возврате в приложение подтягивается облачная копия и **сливается** с локальной: журналы объединяются, удалённые записи и всё до «Сброса» не возвращаются, настройки берутся из более свежей копии.
- Без интернета приложение работает как раньше, отправит данные при следующей связи.
- «Сброс» при входе в аккаунт стирает данные и в облаке.

## Приватность

- PIN на ветках «Партнёр» и здоровье — это замок экрана. В облаке эти данные защищены входом в аккаунт и RLS, но не зашифрованы отдельно: их технически может видеть владелец проекта Supabase.
- Экспорт в разделе «Данные» — резервная копия в виде текста. Хранить её как личные данные.
